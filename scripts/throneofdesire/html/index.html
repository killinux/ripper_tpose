附录 · 手工导出教程

脚本都在 scripts\throneofdesire\，必须在装有游戏的机器上跑（只读游戏目录，产物写到导出根）。 流程：一次性编译两个贴图解码器 → 从 NFS 封包取 NIF/KFM → 解贴图 → Blender 3.6 无头导入建材质、打包、存 blend/FBX。 原理见 docs\throne-of-desire-extraction.md 与 scripts\throneofdesire\README.md。 下面所有命令都在 PowerShell（Windows 11 的 Windows Terminal 默认就是它，或开始菜单里的 Windows PowerShell）里执行，不要用 cmd： 反引号 ` 是 PowerShell 的续行符，& 是调用运算符，.\export_nude_models.ps1 只能在 PowerShell 里直接运行。

这游戏的特别之处

不是 Unreal/Unity：X-Legend 的 HyenaPC 封包层 + NFS 包 + Gamebryo 20.3.3.2 的 NIF/KFM。 FModel、UModel、AssetStudio 都不适用（通用 NifTools/Noesis 对 X-Legend 自定义块的兼容性也没验证过，本流程不依赖它们）， 也不需要任何 AES 密钥或环境变量。 女性 h 系模型本体就是裸模：衣服是附件网格，导入时进默认隐藏的 <编号>_Attachments 集合，FBX 只带基础身体和骨架，不需要 mod 或剥离步骤（例外：导入器对 h997、h999 写死了一张装备表——he50002、he10000+he50000—— 把它们当主体网格；h999 的躯体正是刻意裁掉一截、靠这些网格补全的，所以这两套的预览和 FBX 会连这些部件一起出）。

前提

需要脚本默认位置 / 说明
游戏本体D:\Program Files (x86)\Steam\steamapps\common\ThroneOfDesire（-GameRoot / --game）。 自己的路径在 Steam 库里右键游戏 → 管理 → 浏览本地文件（Steam App 4496710），Steam 库在 C 盘时就是 C:\Program Files (x86)\Steam\steamapps\common\ThroneOfDesire。判定依据是 mobilepack\packageindex 与 mobilepack\FileListPC.txt；--game / -GameRoot 给游戏根或直接给 mobilepack 目录都行
Blender 3.6.15到 blender.org 的 Release 归档下载 Blender 3.6 的 blender-3.6.15-windows-x64.zip，解压到 D:\Program Files\， 得到默认路径 D:\Program Files\blender-3.6.15-windows-x64\blender.exe（-BlenderExe / --blender）。 用 MSI 安装（C:\Program Files\Blender Foundation\Blender 3.6\blender.exe）或放在别处时，第 2 步要补 -BlenderExe '<路径>'， 第 3/4c 步和"重新生成本页"里的 blender.exe 路径都要跟着改，否则 ps1 预检报 Required path not found、 export_model.py 报 Blender not found。 导入器只在 3.6 验证过，别换 4.x。不装 addon：导入器是普通 --python 脚本，FBX 走内置导出器
Python 3PATH 上叫 python（-PythonExe）。新机器从 python.org 安装并勾选 Add python.exe to PATH（或装商店版）， 用 python --version 确认能出版本号——没装时 Windows 11 的 python 是商店的应用执行别名，只会弹商店。 作者机器是 3.13（仓库里有 cpython-313 的 __pycache__）；导出脚本只用标准库，注解都在 from __future__ import annotations 之下，按代码 3.8+ 即可，但只在 3.13 上验证过，稳妥起见建议 3.10 以上 （在 Blender 里跑的导入器和复检脚本用 Blender 自带的 Python，不受影响）。-List 也要用它读编号表： 报 Could not read FEMALE_MODEL_IDS via 'python'、"无法将“python”项识别为 cmdlet…"，或错误里带 Python was not found; run without arguments to install from the Microsoft Store，都是 python 没找到或还是商店别名。 画廊的 make_gallery.py 另需在同一个 python 里 pip install Pillow
WSL + g++编译解码器用一次；之后每次导出也经 wsl.exe 调用它们（Linux 可执行文件），WSL 要一直可用。 新机器先装：管理员 PowerShell 里 wsl --install（默认装 Ubuntu），重启并完成首次用户创建后，在 Ubuntu 里 sudo apt update && sudo apt install -y g++；回到 Windows 用 wsl.exe g++ --version 能出版本号才算就绪。 重启后 Ubuntu 首次启动若报 0x80370102 / WslRegisterDistribution failed，是主板固件里没开硬件虚拟化 （Intel VT-x / AMD-V），进 BIOS/UEFI 打开后再试；WSL 装不起来，第 0 步和之后所有导出都跑不了（脚本只会经 wsl.exe 调用解码器）。 build_codecs.py 用的是 wsl.exe 的默认发行版，装了多个发行版时用 wsl --set-default 指到有 g++ 的那个
本仓库命令按 E:\code\othercode\ripper_tpose 写；解码器默认在仓库根的 .tmp\
导出根D:\throneofdesire_exports；批量脚本默认写其下的 female_all\（-OutputDir）

第 0 步 · 编译解码器（build_codecs.py，只做一次）

cd E:\code\othercode\ripper_tpose
python scripts\throneofdesire\build_codecs.py

联网下载 lzham_codec 与 Ericsson ETCPACK 源码到 .tmp\codec_sources\，用 WSL 的 g++ 编出 .tmp\lzham_v1_decode_raw（贴图 LZHAM 流）和 .tmp\etc_dds_decode （自定义 ETC2/ETCA/EAC4 DDS → TGA）。.tmp\ 不进仓库，新 clone 必须先跑这步。

--output 可换目录，但不建议：export_nude_models.ps1 没有解码器参数，写死找仓库根 .tmp\ 下的两个文件，换了目录第 2 步直接报 Texture decoder(s) missing，没有任何参数能救。真要换，批量只能绕过 ps1 直接跑 python scripts\throneofdesire\batch_export_female.py --game … --blender … --output … --lzham-decoder <路径> --etc-decoder <路径> （也支持 --models、--formats、--no-render、--include-helpers、--force）； 单模型的 export_model.py 显式传 --lzham-decoder/--etc-decoder；第 4b 步的 extract_model_textures.py 里 LZHAM 参数拼作 --decoder（ETC 仍是 --etc-decoder）。

WSL 没装（找不到 wsl.exe）或装了但没有发行版（wsl 打印 Windows Subsystem for Linux has no installed distributions， 脚本随后报 error: Command '…' returned non-zero exit status …）时这步直接失败，后面所有导出都会被解码器预检挡住；按前提表装好 WSL 和 g++ 再跑。 下载到的不是合法 zip（被代理或登录门户页面顶替）时会直接抛 zipfile.BadZipFile 的 traceback（脚本不捕获它），重跑会重新下载，先把网络弄通； 解压中途被打断则不同——源码目录已存在就不再下载，之后报 error: lzhamdecomp sources were not found 或 g++ 找不到文件， 删掉 .tmp\codec_sources\ 整个目录再跑一次。

第 2 步 · 批量路径：13 套女性基础体（export_nude_models.ps1）

cd E:\code\othercode\ripper_tpose\scripts\throneofdesire

.\export_nude_models.ps1                         # 全部 13 套 -> blend + fbx + 预览，已完整的自动 skip

它包装 batch_export_female.py，后者对每个编号调一次第 3 步的 export_model.py。 跑前预检两个解码器、游戏目录、Blender 是否存在。一套的 6 个产物（source\<id>.nif、 source\<id>.kfm、textures\textures_manifest.json、blend、fbx、预览）都在且非空就记 skipped， 否则重导；逐条合并进 female_all\female_export_manifest.json。

第 3 步 · 单模型路径：任意编号（export_model.py）

cd E:\code\othercode\ripper_tpose
python scripts\throneofdesire\export_model.py `
  --game 'D:\Program Files (x86)\Steam\steamapps\common\ThroneOfDesire' `
  --model h996 `
  --blender 'D:\Program Files\blender-3.6.15-windows-x64\blender.exe' `
  --output 'D:\throneofdesire_exports' `
  --formats blend fbx `
  --render

一条命令依次：提取 NIF/KFM → 按 NIF 引用的 DDS 名找出全部相关 NFS 包并解贴图（h996 复用 h001 身体贴图、 h999 的 he10000/he50000 补全装备这类跨包依赖自动处理）→ Blender 导入建材质、打包、存 blend/FBX、渲预览 → 写 export_manifest.json。产物在 <--output>\<编号>\，目录已存在时原地覆盖。 hm*、m* 也可以用这条命令试，但文档正式验证的只有 h 系（h005 端到端、13 套批量）；仓库画廊里另有 hm003 单独导过一次 （9 网格、1 骨架、6 贴图全打包、有预览），294 个 m* 一个都没导过。主体网格判定按 <编号>_ 前缀 （h997/h999 另有写死的 he* 装备表，h011 按底色贴图名兜底），跨包贴图按文件名前 4 位配对；这些在 hm*/m* 上 失败时属于未验证范围，不是环境问题。 注意：写到 D:\throneofdesire_exports 根下的本页归为"单独导出"，写到 …\female_all 才算"批量裸模"。

第 4 步 · 分步手工（只在排查时需要）

cd E:\code\othercode\ripper_tpose
# 4a 取 NIF/KFM -> h005.nif、h005.kfm、manifest.json（含 SHA-256）

# 4b 解贴图 -> DDS + TGA + textures_manifest.json（跨包依赖：--model 换成包主人如 h001，--nif 不变，再跑一次；包主人怎么认见下文）
python scripts\throneofdesire\extract_model_textures.py `

  --decoder '.tmp\lzham_v1_decode_raw' --etc-decoder '.tmp\etc_dds_decode' --output '.tmp\throneofdesire\h005\textures'

# 4c Blender 导入（另可加 --fbx <路径>、--render <路径>、--include-helpers）
& 'D:\Program Files\blender-3.6.15-windows-x64\blender.exe' --background `
  --python 'E:\code\othercode\ripper_tpose\scripts\throneofdesire\import_xlegend_nif36.py' -- `
  --input '.tmp\throneofdesire\h005\source\h005.nif' --textures '.tmp\throneofdesire\h005\textures' `

4b 的"包主人"怎么认。包主人 = DDS 文件名前 4 个字符，也就是它所在的 NFS 包（文件名以 h001 开头的归 h001， 以 he50000 开头的归 he50）。先用 python scripts\throneofdesire\inspect_materials.py --nif <nif> 看每个 shape 的 textures（只列顶点数 > 100 的 shape，小的辅助网格不会出现），凡是前 4 位不等于本编号的， 就用那 4 位当 --model 再跑一次 4b （--nif、--output 不变）；只有主体 shape 引用的跨包贴图才需要补。注意每次运行都会覆盖 --output 下的 textures_manifest.json，要留底就先改名；第 2/3 步走 export_model.py 时会自动按包主人拆成 textures_manifest_<包主人>.json 并写汇总清单。

参数表

参数作用
-List列 13 套编号、状态（COMPLETE / PARTIAL / MISSING，只看 blend/fbx/预览三个文件）和产物目录，不导出
-Only h005,h020子集；只接受 13 个女性编号，其它报 Unknown。清单按固定顺序合并，不丢别的记录
-Format blend,fbx只认 blend、fbx，缺省两者都出；写 xps 直接报错
-Force产物齐全也重导，原地覆盖该编号目录下的旧产物（blend/fbx/预览/source/textures）；不加时齐全的记 skipped。 只覆盖本次要求的那些产物：-Format blend -Force 不碰旧的 .fbx、-NoRender -Force 不碰旧的预览 PNG， 它们会作为和新 blend 不同批的过期文件留在目录里——而 -List 仍报 COMPLETE、-ValidateOnly 也会拿这个旧 FBX 通过。 要整套重做就用默认参数（blend+fbx+预览）跑 -Force
-NoRender不渲 720×960 正面预览 PNG。预览走 EEVEE，需要本机显卡驱动能建 OpenGL 上下文；远程桌面或无显卡环境下渲染失败导致整套 failed 时，加 -NoRender（export_model.py 去掉 --render）先出 blend/fbx
-IncludeHelpers把碰撞体 / 调试辅助网格也导入
-ValidateOnly不导出，用 Blender 重开 blend 与 FBX，报告写 female_export_validation.json。 它默认复检全部 13 套，且每套同时要 blend 和 fbx：只导了子集时必须带同样的 -Only（如 -ValidateOnly -Only h005,h020）， 否则没导的记 FAILED 并报 N export(s) failed validation；用 -Format blend 导的没有 fbx，过不了复检
-GameRoot / -BlenderExe / -OutputDir / -PythonExe覆盖前提表里的默认值
export_model.py：--game --model --blender --output四个必填
--formats blend fbx / --render / --include-helpers空格分隔；含义同上，--render 默认关
--lzham-decoder / --etc-decoder解码器路径。默认值只在 export_model.py 里 （<仓库>\.tmp\ 下的两个文件，路径按脚本位置算、与当前目录无关）；batch_export_female.py 有同名参数但没有默认， 不传就由它调用的 export_model.py 用自己的默认；ps1 没有这两个参数

  tod_models_manifest.json             collect_manifest.py 的画廊清单
  _gallery\thumbs\<组>_<模型>.jpg    make_gallery.py 的缩略图

blend 里三个集合：<编号>_Base（身体/脸/发）、默认隐藏的 <编号>_Attachments（衣服等附件）和放静止骨架的 <编号>_Skeleton，网格物体带自定义属性 xlegend_category = base / attachment。底色贴图默认接好 （跨模型遮罩叠层例外：贴图已载入但不接，见材质自定义属性 xlegend_base_status），法线/高光/光泽只挂在节点里。

容易踩的坑

报 Texture decoder(s) missing。没跑第 0 步，或换了新 clone（.tmp\ 不进仓库）， 或 build_codecs.py --output 编到了别处（ps1 只认仓库根 .tmp\）。跑一次 build_codecs.py；它要 WSL 里有 g++ 且能联网。
报 WSL decoder requires a drive-qualified path。解码器经 wsl.exe 跑， 路径被换算成 /mnt/<盘符>/…，导出根和仓库都得在本地盘符下，UNC 和映射盘不行。为稳妥起见，仓库和导出根 （-OutputDir / --output）路径别带空格和中文——这些路径会原样拼进 wsl.exe 的命令行； 游戏目录只在 Python 侧读取，含空格没关系。
报 Unsupported packageindex version 0x…; expected 0x20190503。游戏更新换了封包索引格式， 脚本只认 0x20190503（本页流程在该版本上验证），不是环境问题，需要改 extract_nfs.py。

重跑秒回 already complete。产物齐全时默认 skip（断点续跑的设计）；要重做加 -Force。 注意 -List 的 COMPLETE/PARTIAL 只看 blend/fbx/预览三个文件，而批量 skip 判定要 6 个产物（另含 source\ 的 nif/kfm 和 textures\textures_manifest.json）都在且非空，且只按本次 -Format/-NoRender 要求的产物算—— 删过 source\ 或 textures\ 的模型 -List 仍是 COMPLETE 但会被重导； -Format blend -NoRender 时 -List 报 PARTIAL 的反而可能被 skip。

模型整体一个颜色 / 全白。手工 4b 漏了 --etc-decoder，只有 DDS 没有 TGA；导入器只按 DDS 的 stem 在 --textures 目录找 .tga/.png。补上再跑。

皮肤平、没法线细节。有意为之：EAC 法线通道约定未验证完，接上会让皮肤斑驳，法线节点默认断开，要用自己连。

手工分步时 h996 / h999 缺贴图。它们的贴图在别的包（h001 身体、he10/he50 装备），4b 要按包主人多跑几次； 第 2/3 步会自动处理。

并行与耗时

批量脚本没有分片/lane 参数，13 套顺序跑。别开两个 export_nude_models.ps1 写同一个 -OutputDir： 清单是启动时读一次、每套写一次的合并模式，会互相覆盖记录。要并行就开几个窗口直接跑 export_model.py，各自只写自己的 <编号>\（该目录已有产物会被原地覆盖）：

cd E:\code\othercode\ripper_tpose
python scripts\throneofdesire\export_model.py `
  --game 'D:\Program Files (x86)\Steam\steamapps\common\ThroneOfDesire' --model h005 `
  --blender 'D:\Program Files\blender-3.6.15-windows-x64\blender.exe' `
  --output 'D:\throneofdesire_exports\female_all' --formats blend fbx --render
# 全部跑完后再执行一次批量脚本（不加 -Force），它把每套记为 skipped 并补齐完整清单
.\scripts\throneofdesire\export_nude_models.ps1

耗时大头是每张贴图两次 wsl.exe 往返（先对包里每个 LZHAM 流解一次，h005 一个包就有 35 个；再对每张映射到的 DDS 调一次 ETC 解码转 TGA，h005 是 34 张）和 Blender 打包；实际导出的每套秒数记在清单的 duration_seconds（skipped 的没有这个字段）， 已完整的模型 skip 只要几秒。

重新生成本页

cd E:\code\othercode\ripper_tpose\scripts\throneofdesire
& 'D:\Program Files\blender-3.6.15-windows-x64\blender.exe' --background --factory-startup --python html\collect_manifest.py
python html\make_gallery.py                 # 加 --force 强制重做缩略图

collect_manifest.py 递归扫导出根下全部 .blend，逐个打开统计网格/面/骨架/材质/贴图打包数 （缺骨架、缺贴图、贴图未打包记为告警），female_all\ 下归批量裸模、其余归单独导出，并入 female_export_manifest.json 的状态，写 <导出根>\tod_models_manifest.json （导出根不在默认位置时在 -- 后面依次传导出根和 manifest 路径）。 make_gallery.py（--source-root / --manifest / --out / --thumb-dir / --force） 把预览图缩成 720 宽 JPEG 放进 _gallery\thumbs\，按 <组>_<模型>.jpg 命名（同一编号可能两组都有）， 再重写 html\index.html。清单和缩略图留在导出根，只有 index.html 进仓库——仓库不收任何游戏素材。

例外与已知限制

  • 批量名单只有 13 套女性 h 系；hm* 是复合场景组，刻意不进名单；294 个 m* 未分类，需要的用第 3 步单个导。
  • 产物是静态网格 + 未蒙皮的静止骨架：蒙皮权重和 KFM 动画曲线尚未恢复，骨架只能看不能摆姿势。
  • 只出 blend 和 FBX；XPS 不支持，交换格式用 FBX。
  • EAC 法线贴图保留在节点但默认断开；编号没有对应角色名。
  • NFS 包尾偶有未被 NIF 引用的旧贴图流，只作为 unmapped_streams 记进按包主人拆出的 textures_manifest_<包主人>.json（只手工跑 4b 时记在 textures_manifest.json 里），不导出。
