附录 · 手工导出教程

脚本都在 scripts\doa5lr\，必须在装有游戏的那台机器上跑（Windows PowerShell 5.1）。 链路：.bin/.lnk 封包 → extract_lnk.py 解出 TMC/TMCL → 32 位 Noesis 转 FBX + DDS → Blender 无头组装成带贴图的 .blend 并渲预览。日常只需 export_full.ps1 一条命令。原理见同目录 README.md，更多用例见 EXPORT_GUIDE.md。

第一步 · 查条目名（extract_lnk.py --list）

以下所有命令都在仓库的 scripts\doa5lr\ 目录里执行（把 E:\code\othercode\ripper_tpose 换成你 clone 的位置）。.ps1 通过 $scriptDir 找同目录的 extract_lnk.py/build_blend.py，用绝对路径调用也行；但 ..\doa6\import_mod.ps1、html\... 这类相对写法要求当前目录正确。

cd E:\code\othercode\ripper_tpose\scripts\doa5lr
$game = "D:\Program Files (x86)\Steam\steamapps\common\Dead or Alive 5 Last Round"

python extract_lnk.py "$game\chara_initial.bin" --list --filter "KASUMI*"       # 霞在该封包的全部条目
python extract_lnk.py "$game\chara_common.bin"  --list --filter "*_HAIR_*.TMC"  # 该封包里的发型（霞/绫音的在 chara_initial，要再查一次）
.\export_character.ps1 -List                                                    # 无过滤地列 chara_common 全部 2867 条；不能带 --filter，要筛用上面的 python

每行 序号 真实名 flags 大小 @偏移。--filter 是 fnmatch 通配符、不分大小写，KASUMI* 会连 KASUMI_BOSS_* 和 --H/--HL 物理文件一起列出，要精确写 KASUMI_COS_*.TMC。模型分散在 36 个封包：常规服装/发型在 chara_initial 与 chara_common，过场版在 rtm_common，后期 DLC 在 patch_XX_catalog。export_full.ps1 首次运行会扫全部 .bin 写出 D:\doa5lr_exports\_archive_index.txt（每行 条目名 封包），之后直接查它：

Select-String '^KASUMI_(COS|DLC|DLCU)_\d+ ' D:\doa5lr_exports\_archive_index.txt

建索引时 extract_lnk.py 的 stderr 被 2>$null 吞掉，脚本又是 $ErrorActionPreference = "Stop"：doaKey/file5lr.dat 没放对时， 「建立封包索引」之后只会看到一行类似 python.exe : Traceback (most recent call last): 就中止，真正的原因（哪个文件找不到）看不见，索引文件也不会生成。 所以首次运行前务必先用上面的 extract_lnk.py --list 跑通一次（这一步能看到完整报错）；建完索引后检查 (Get-Content D:\doa5lr_exports\_archive_index.txt).Count，正常约 1099 行（TMC 总数），明显偏少说明有封包解析失败，修好后删掉该文件再跑。

第二步 · 一键出带材质 blend（export_full.ps1）

.\export_full.ps1 KASUMI_COS_001 -Face auto -Hair 001 -Label KASUMI_Kasumi            # 默认服装
.\export_full.ps1 KASUMI_COS_002 -Face auto -Hair 001 -Label KASUMI_Kasumi_COS_002    # 换装：脸/发型已提取过就复用
.\export_full.ps1 HONOKA_COS_001 -Face auto -Hair HONOKA_HAIR_002 -Label HONOKA_Honoka_COS_001   # -Hair 也可给完整名

脚本依次：查索引定位封包并调 export_character.ps1 解出 TMC/TMCL → Noesis ?cmode 转 FBX，同目录落下 Tex_NN(L_x).dds → 每张 DDS 再转同名 PNG（Blender 读不了部分 BC 格式）→ build_blend.py 按 服装 → 脸 → 头发 顺序导入，只在部件确实不在身体坐标系时才搬， 把 1.6 cm 高的模型归一到约 1.7 单位，按 Diffuse/Normal/Specular 重建 Principled 材质，打包贴图，EEVEE 渲 900×1400 预览。 正常会依次打印 FBX_IMPORTED=3、PART_ALIGNED（脸、发各一行，单部件时没有）、SCALE_NORMALIZED、MATERIALS_REBUILT、IMAGES_PACKED、 SAVED_BLEND、SAVED_PREVIEW、BUILD_BLEND=PASS，最后绿色 OK <Label> (xx MB)。单套 5–16 秒。

-Label 按 <角色>_<英文名>_<COS|DLC|DLCU>_<NNN> 起（默认装可省尾缀）：画廊靠文件名解析服装号，带中文或多余下划线的 会被当成 COS_001。目标 blend 已存在时打印 SKIP 返回，加 -Force 才重做。

批量 · 一个角色的全部服装

$entries = Get-Content D:\doa5lr_exports\_archive_index.txt |        # 先单跑过一次第二步，索引才存在
  ForEach-Object { if ($_ -match '^(KASUMI_(COS|DLC|DLCU)_\d+) ') { $Matches[1] } } |
  Sort-Object -Unique
foreach ($entry in $entries) {
  $suffix = $entry.Substring($entry.IndexOf('_') + 1)                 # COS_002 / DLC_011 / DLCU_003
  if ($suffix -eq 'COS_001') { continue }                             # 默认装已按 KASUMI_Kasumi 出过，Label 不同不会 SKIP
  try   { .\export_full.ps1 $entry -Face auto -Hair 001 -Label "KASUMI_Kasumi_$suffix" }
  catch { Write-Warning "$entry : $_" }                                # 占位条目会抛错，别让它中断循环
}

换角色只改正则和 Label 前缀。已有 blend 自动 SKIP，中断后重跑即续传。头发一律 -Hair 001——每套服装的官方默认发型无法从条目名得知， 要别的发型用 -Hair 003 之类另出一份。

只要 FBX + DDS（export_character.ps1）

.\export_character.ps1 HONOKA                                 # HONOKA_* 全部条目（含发型），一个条目一个子目录
.\export_character.ps1 KASUMI_COS_002 -Archive chara_initial   # 指定封包；缺省 chara_common，不是 auto
.\export_character.ps1 HONOKA -NoConvert                       # 只解 TMC/TMCL，不转 FBX

产物在 D:\doa5lr_exports\<名字>\<条目>\：.TMC/.TMCL/.fbx + Tex_NN(L_x).dds（L 全尺寸、M 小 mip）。<条目>\ 子目录只在转换那一步建， -NoConvert 不建它——.TMC/.TMCL 直接躺在 D:\doa5lr_exports\<名字>\ 下，不是解包失败。 目录已存在会 SKIP，-Force 则整个删掉重建（Remove-Item -Recurse）。

官方内容没有 nude。36 个封包、12,625 个条目名搜 nude/naked/bare/skin/under/lingerie 零命中。 mod 就是替换用的 .TMC + 同名 .TMCL，格式与官方一致，-TmcFile 直接吃（给目录则取第一个 .TMC），缺 .TMCL 会警告并出白模；中转目录 D:\doa5lr_exports\_mods\<TMC名>\——每次跑到这一步都会先整个删掉再重建（与 -Force 无关，只有目标 blend 已存在 SKIP 时才不动），别把手改的文件放在里面。-Face auto/-Hair 001 靠位置参数里的角色名推导前缀， 纯 mod 请用 -FaceTmc/-HairTmc。mod 在 GameBanana 上是 0 个，主要在 LoversLab（需登录手动下载）。

..\doa6\import_mod.ps1 是 DOA5/DOA6 通用脚本，按扩展名自动判别 TMC/g1m：产物在 D:\doa_mod_fbx\<zip 或目录名>\（-OutRoot 改；此脚本既没有 SKIP 也没有 -Force，重跑同一个 zip/目录会直接覆盖该目录里的同名 FBX/DDS）； zip 会先解压到 D:\doa_mods\_extract_tmp\<名字>\（硬编码；解压前该目录若已存在会先整个删掉，处理完再删一次，-KeepExtracted 只是保留处理完那一次）；32 位 Noesis 路径用 -Noesis32 指定（不是 -NoesisExe）。

export_full.ps1 参数表

参数作用
位置参数 <条目名>服装条目，自动转大写；也是 -Face/-Hair 推导前缀的来源
-Face auto用 <角色>_FACE；给带下划线的完整名则转大写后直接用
-Hair 001编号（写满三位）或完整名 KASUMI_HAIR_001
-Archive auto缺省，每个部件各自查索引；手动指定（如 chara_initial）时三个部件共用同一封包
-Label产物文件名；缺省用条目名或 mod TMC 文件名
-TmcFile / -FaceTmc / -HairTmc外部 TMC 文件或目录，替代对应部件
-Force覆盖已有 blend，并把三个部件目录 <OutRoot>\<条目>\ 整个删掉重解（Remove-Item -Recurse，里面手改、手补的文件一起没）。注意不给 -Force 也可能重解：脚本判定复用只看 <OutRoot>\<条目>\<条目>\<条目>.fbx 在不在，不在（上次 Noesis 失败，或先用 -NoConvert 只解过 TMC）就固定带 -Force 去调 export_character.ps1，同样是整个删掉重建，别把手改的文件放在里面
-NoPreview不渲预览图。预览用 EEVEE 渲染，需要 GPU/OpenGL：在 VM、远程桌面或无显卡机器上渲染失败时 blend 其实已先存好（已打印 SAVED_BLEND，脚本仍显示 OK 但没有 SAVED_PREVIEW），加 -NoPreview 跳过即可，画廊显示「无预览图」
-GameRoot / -OutRoot / -PythonExe / -NoesisExe / -BlenderExe只对 export_full.ps1 自己的步骤（建索引、DDS→PNG、mod TMC 转换、Blender 组装）生效；内部调用的 export_character.ps1 只收到 -Archive/-OutputRoot（即 -OutRoot）/-Force，不接收 -GameRoot/-PythonExe/-NoesisExe，解包那一步仍用它自己的默认值——游戏不在默认路径会直接抛 archive not found。路径不同的机器请直接改两个 .ps1 param() 块里的默认值（export_full.ps1 第 31–35 行、export_character.ps1 第 14–18 行）和 extract_lnk.py 的 DEFAULT_TOOLS_DIR = r"E:\tools\doa5lr"，或干脆把工具装到前提表的默认路径

并行与耗时

脚本没有分片参数，并行就是开几个 PowerShell 窗口各跑一份上面的循环，按角色切分。先在单窗口跑通任意一套（让索引建好，首次要扫 36 个封包） 再开并行；脸/发型目录已存在就复用，不同路之间不要用 -Force。实测单套 5–16 秒：COS/DLC 的 223 套三路并行跑完，DLCU 的 47 套随后同法补出，合计 270 套换装；19 人默认装当初是 19 路并行 129 秒。画廊现共 291 个模型（19 默认装 + 270 换装 + 2 件早期 KASUMI_DLC_011 对照件）。 -NoPreview 省掉的只是一次 EEVEE 渲染。
