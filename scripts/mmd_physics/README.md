# MMD / PMX 物理：胸部调参、衣服碰撞与标定

这个目录的工具和具体游戏无关，只要是带物理刚体的 PMX 都能用。它回答三个问题：

1. 胸部的刚体和关节参数该设多少才自然；
2. Blender 预览为什么和 MMD 不一样，怎样让它更接近 MMD；
3. 衣服、头发为什么穿过身体，怎样让它们碰得到身体（第 5 节）。

背景调研见 `reports/胸部物理实现方式调研.md`。

| 文件 | 在哪跑 | 做什么 |
|---|---|---|
| `tune_bust_pmx.py` | 普通 Python（只用 mmd_tools 自带的 `pmx` 模块，不开 Blender） | 改写现有 PMX 的胸部关节（限位、弹簧）和胸部刚体的阻尼，另存一个新 PMX。所有参数都有默认值，也都能在命令行改 |
| `cloth_collision_pmx.py` | 普通 Python（`pmx` 模块 + numpy） | 按裸体皮肤重新量身体碰撞体（或从同骨架的模型抄），再让每个会动的衣服、头发刚体都和身体碰撞（第 5 节） |
| `clip_test_blender.py` | Blender（后台） | 跳一段舞，逐帧数会动的顶点有多少陷进身体（第 5 节的数字就是它算的） |
| `physics_calibration_pmx.py` | 普通 Python | 生成一个标定模型：一个自由下落的方块（测重力），五个带弹簧的摆臂（测弹簧的实际强度） |
| `calibration_blender.py` | Blender（后台） | 在 Blender 里按 60 / 120 / 300 Hz 跑标定模型，给出预测值和截图，用来和 MMD 的结果对照 |
| `mmd_like.py` | Blender 内被导入 | 让 mmd_tools 导入的关节按 MMD 的方式工作；`scripts/riseoferos/render_pmx_dance.py` 的最后一个参数写 `mmd` 时调用它 |

## 1. 胸部参数：先算重力，再配弹簧

`tune_bust_pmx.py` 不靠猜参数，而是按重力来算：

- **弹簧：** 胸在重力下的静止下垂角 = 重力力矩 ÷ 弹簧。所以先定下垂角（`--sag`），再反推弹簧。
- **重力力矩：** 要把挂在胸上的所有刚体都算进去。
- **晃动频率：** 约为 √(弹簧 ÷ 转动惯量) ÷ 2π。脚本会打印出来。

```powershell
python tune_bust_pmx.py in.pmx out.pmx                                  # 默认：下垂 15°，阻尼 0.95
python tune_bust_pmx.py in.pmx out.pmx --sag 8 --lin-damp 0.99 --ang-damp 0.99
python tune_bust_pmx.py in.pmx - --dry-run                              # 只打印，不写文件
```

| 参数 | 默认 | 含义 |
|---|---|---|
| `--gravity` | 98 | MMD 重力，单位是模型单位/秒²（9.8 × 10；three.js MMDPhysics、saba、MMDAgent-EX 都用这个值） |
| `--sag` | 15 | 静止时胸往下垂的角度（俯仰），俯仰弹簧由它反推 |
| `--twist-sag` | 4 | 绕前后轴的静止侧倾，扭转弹簧由它反推 |
| `--yaw-scale` | 1 | 左右弹簧 = 俯仰弹簧 × 这个倍数 |
| `--spring-pitch/-yaw/-twist` | 不设 | 直接指定弹簧值，覆盖上面的推算 |
| `--pitch-limit / --yaw-limit / --twist-limit` | 25 / 20 / 5 | 转动限位（±度） |
| `--lin-damp / --ang-damp` | 0.95 / 0.95 | 胸部刚体的移動減衰 / 回転減衰 |
| `--hanging-scale` | 0.2 | 挂在胸上的刚体（吊坠等），质量和它们自己关节的弹簧一起乘这个倍数；1 表示不动 |
| `--mass` | 不改 | 胸部刚体的质量 |
| `--bones` | `胸\|乳\|chest\|breast\|bust\|oppai` | 用骨骼名或关节名找胸部关节 |

轴向按关节自己的坐标系：X = 俯仰（上下），Y = 左右，Z = 绕前后轴扭转。ROE 导出的关节旋转都是 0，所以就是世界坐标轴。

**挂件的重量必须算进去。** g05 每侧胸下面挂着 3 节吊坠刚体，每节质量 1，和胸自己一样重。它们产生的力矩是胸自身的 3.4 倍。按胸自身重量算出来的弹簧根本撑不住，胸会直接垂到限位上。现在的处理分两步：

- 挂件的质量和它们关节的弹簧同乘 0.2。弹簧和质量的比值不变，所以吊坠自己怎么晃不变，只是拖胸的力小了 5 倍（吊坠本来就比胸轻）；
- 剩下的重量照样计入胸部弹簧的计算。

**输出文件的贴图路径。** `pmx` 模块读文件时会把贴图路径变成绝对路径，写文件时再改成相对于新文件的路径。所以新 PMX 如果写在别的文件夹，贴图会指回原文件夹（`..\pmx\...`）。脚本的处理是：如果输出旁边有一份拷过去的 `textures\`，就保持原来的相对路径。

## 2. Blender 预览和 MMD 差在哪里（`mmd_like.py`）

mmd_tools 把每个 PMX 关节建成 Blender 的 Generic Spring 约束，6 个轴的弹簧全开，其余都用 Blender 的默认值。这些默认值和 MMD 有三处不同，而且都会让预览显得比 MMD 更硬、更稳：

1. **弹簧类型和阻尼。** 默认是 SPRING2（btGeneric6DofSpring2），每个轴带 0.5 的阻尼。这个阻尼作用在关节的相对运动上，弹簧刚度为 0 时也照样起作用。MMD 没有这一项：PMX 关节本身没有阻尼字段，MMD 用的 Bullet 2.75 也是老的 btGeneric6DofSpring。g05 现行模板在旧预览里胸几乎不动，主要就是这个原因。
   - 改法：换成 SPRING1。
   - 注意：Blender 把 SPRING1 的阻尼**取反**后才交给 Bullet（`1 - 值`，见 `intern/rigidbody/rb_bullet_api.cpp`）。所以要得到 Bullet 的默认 1.0（也就是 MMD 的实际值），Blender 里得设 **0**。设成 1 的话，弹簧只会刹车、不会往回推，任何弹簧值都会垂到限位上。这是实测踩到的坑。
2. **角弹簧单位。** mmd_tools 把 PMX 的回転ばね原样拷进 Blender，没做单位换算。按 0.08 缩放导入时，结果硬了 1/0.08² ≈ 156 倍。
   - 改法：乘缩放比的平方。
   - 線形ばね（移動ばね）的单位与缩放无关，不用换算。
3. **重力。** 按 0.08 导入时，MMD 的 98 单位/秒² 对应 7.84 m/s²。Blender 默认的 9.81 大了 25%。

**标定结果**（`calibration_blender.py`，Blender 3.6）：做完上面三处转换后，按胡克定律应该下垂 10° 的摆臂，在 60、120、300 Hz 下分别停在 9.6°、9.5°、9.8°。自由下落的方块 0.5 秒落了 12.3–12.7 单位，1 秒落了 49 单位，和重力 98 吻合。也就是说，转换后的 Blender 里，PMX 弹簧就是它数值所表示的理想弹簧。只有特别硬的弹簧（该摆臂的 30 倍以上）在 60 Hz 下会变软。

**仍然不同的地方：** MMD 的关节限位是"软"的，Blender 的是"硬"的；MMD 自己的物理步长没有公开资料。所以最终效果还是要在 MMD 里看。

用法：

```powershell
blender -b --python ..\riseoferos\render_pmx_dance.py -- in.pmx in.vmd bgm.wav out.mp4 0 chest mmd        # 重力 98
blender -b --python ..\riseoferos\render_pmx_dance.py -- in.pmx in.vmd bgm.wav out.mp4 0 chest mmd:9.8:4  # 重力 9.8，每帧 4 个子步
```

## 5. 衣服、头发碰身体（`cloth_collision_pmx.py`，2026-10-06）

**问题出在哪（Vindictus Fiona）：** 头发、裙子、肩布、背后的长围巾，171 个会动的刚体一个都不和身体碰撞。原因有两层：

1. **身体碰撞体量错了。** Convert_to_MMD5 的「身体碰撞刚体(自动)」按「这根骨头带的所有顶点」量半径，取 85% 分位。穿着盔甲导出时，盔甲的顶点也算进去了。mmd_cloth_physics 给锚骨补的刚体也是这样量的。结果是上臂碰撞体有手臂的两倍粗，大腿 1.6 倍；挂长围巾的 上半身5 锚点成了半径 15 cm 的球，把脖子、后脑的头发整个包在里面。
2. **所以几乎每块布、每缕头发一开始就在碰撞体里面。** mmd_cloth_physics 把这种刚体放进「贴身组」（10 组），这个组什么都不碰，本来是为了防止开场被弹飞。Fiona 的头发用的是「饰品」预设（为了保住波波头的形状），没被当成头发，也走了这条路。

**这个工具做两件事：**

1. **按裸体皮肤重新量身体碰撞体**（`--skin` 写裸体的材质名，可用通配符）：
   - 手臂、腿：轴线沿肢体截面的中心拟合（骨头一般不在肢体正中），半径取那一段皮肤最窄的一侧。大腿上粗下细（Fiona 顶部 8.5 cm、膝盖 4 cm），模型在同一条腿上还有第二个碰撞体时就拆成上下两段：大腿上的 足D、上臂上的 腕捩 和 足 / 腕 动作完全一样，上半段给一个，下半段给另一个；
   - 肩：沿 肩→腕，厚度到肩顶的皮肤为止。脖子：首→頭，用脖子一整圈皮肤来量。脖子前面的皮肤权重在头上，只用脖子的权重会量偏；
   - 头：头骨里能放下的最大的球。耳朵往外凸，眼眶、嘴是往里凹的，所以分两刀量：前后上下看正中那一条剖面的外轮廓，左右只看球心那个高度的头侧皮肤。脸和下巴另加一个球（頭2），垂在脸颊、下巴前面的侧发靠它挡；
   - 躯干：横放的胶囊，每个都取在侧面轮廓（前后，不算胸）和宽度以内能放下的最大的那个。两个相距很远的躯干碰撞体之间，如果有一根没碰撞体的脊椎骨，就给它补一个（Fiona 的 上半身4，胸口高度）。
2. **让每个会动的刚体（胸除外）都尽量碰得到身体：**
   - 静止时陷在碰撞体里的，先把它削薄：盒子只削一个轴，胶囊削半径。刚体的形状只管碰撞，削薄不影响网格；
   - 削到原来的 35% 还不够，就只对那一类碰撞体关掉碰撞，其余照碰。碰撞体分五类：头、脖子、躯干、手臂、腿。
   - 为什么要分类：MMD 只能按组过滤碰撞，所以每一类碰撞体单独占一组，每种「碰哪几类」的组合再占一组。

不加、不删、不挪任何刚体，关节一个不动。

**别的模型上补的几条（ROE Inase a08，10-06）**：这些都只在出问题时起作用，Fiona 的结果逐字节不变。

- 网格稀的身体，有的切片只采到前胸、没采到后背（前 -1.42、后 -1.29，躯干实际 1.8 深）。和上下 0.35 以内的邻层差太多的切片
  不算，胶囊不受它约束。一圈特别密的顶点（裆部）把宽度拉窄的切片也一样处理。
- 下半身的碰撞体可以从导出时的位置往上找到骨盆：Inase 的原来放在两腿分叉的高度，圆胶囊只能做到半径 4 cm，中段还穿过
  两腿之间的空隙。现在在骨盆，半径 9 cm。往上找以后仍会伸进裆部空隙，那里不挂布，不碍事。
- 下巴球：脸部网格到下巴就结束的模型，喉咙是身体网格，只看脸会让球长进脖子。所以下巴球露出皮肤超过 100 个顶点时，
  就把脖子的皮肤也算上、往下也设上限重新找。剩下「在球里面」的顶点，法线朝里、离脸前 5–9 cm，是口腔内部，不算露出。
- 原来的碰撞体已经在皮肤里面、又不比新量的小（Inase 的脖子），就保留原来的。

```powershell
python cloth_collision_pmx.py Fiona_full.pmx Fiona_full_new.pmx --skin "4_BaseBody-MI-pc-female-body05_0.1_0_0,4_BaseBody-MI-pc-female-handfoot05_0.1_0_0,4_Face-MI-Fiona-Face01_0.1_0_0_nude"

```

| 参数 | 默认 | 含义 |
|---|---|---|
| `--skin` | 必填 | 裸体皮肤的材质 |
| `--inset` | 0.02 | 碰撞体比皮肤缩进去多少（PMX 单位，1 = 8 cm） |

| `--keep-colliders` | 关 | 不重新量身体碰撞体，只改碰撞组 |
