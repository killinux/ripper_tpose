附录 · 手工导出教程

脚本都在 scripts\vindictus\，产物默认落在 D:\vindictus_exports（-ExportRoot）。这套和别的游戏最大的不同： 游戏没发售（Steam 商店页写 2027），能拿到的只有 2024-03-14 那次 Pre-Alpha 测试的客户端，而且它的 pak/utoc 索引是 AES 加密的， key 不在任何公开网页上——要自己从 exe 里算出来（find_aes_key.py，一分多钟）。顺序固定：装客户端 → 算 key → list_models.py 看清单 → export_model.ps1 <模型> 出带贴图、一副骨架的 .blend → 重生成本页。 以下所有命令都在 〈仓库〉\scripts\vindictus 里跑，每开一个新窗口先 cd 进去。

前提 · 工具与默认路径

工具脚本默认路径 / 说明
客户端archive.org 项目 vindictus-defying-fate.-7z（Vindictus_Defying_Fate.7z，15,150,318,532 字节，md5 801374e112f438af9d401579c75fc6c1， 种子在同一页）。解压后把压缩包顶层的 Vindictus\ 当游戏根放到 E:\tools\vindictus（-GameRoot）， 即 E:\tools\vindictus\Vindictus.exe 和 E:\tools\vindictus\Vindictus\Content\Paks\Vindictus-Windows.ucas（15.04 GB）。 国内直连 archive.org 不通、普通 HTTP 代理只有几十 KB/s——走本机 VPN 客户端的系统代理端口并开 8 个 Range 连接可到 14 MB/s（20 分钟）。 2025-06 的 Alpha Demo（Steam 3576170）测试结束后被换成 348 MB 空壳，下不到。
UE Viewer必须是 spiritovod 的 UE5 specific build：Gildor 论坛 https://www.gildor.org/smf/index.php?topic=7906.0 首帖的 Google Drive umodel_materials.zip，取里面的 umodel_materials_ue5.exe（本机是 build 1579 based fix282 / 2026-09-05）放到 E:\tools\umodel_specific\materials\（-UmodelExe）。Oodle 已内置，不需要额外 dll；官网普通版对 UE 5.3 会报 Serializing behind stopper。E:\tools\umodel_stellarblade、umodel_ff7remake 那两个专用版不能用在这里。
Blender 3.6.15D:\Program Files\blender-3.6.15-windows-x64\blender.exe（-BlenderExe），须先装好并启用 io_scene_psk_psa 5.0.6 （https://github.com/DarklightGames/io_scene_psk_psa/releases/tag/5.0.6，别拿面向 4.x 的新版）。脚本用 --factory-startup 跑， 自己 addon_utils.enable 这个插件，所以只要装在用户目录即可，不必在偏好里勾选。
Python 3python 要能直接调起 Python 3；pip install cryptography Pillow——前者解 utoc 目录索引和试解密 pak 索引，后者出缩略图。
PowerShell未签名脚本，第一次跑先在当前用户范围放开执行策略（RemoteSigned），按 .\export_model.ps1 调用。

第零步 · 算 AES key（find_aes_key.py，只做一次）

cd 〈仓库〉\scripts\vindictus
python .\find_aes_key.py --out E:\tools\vindictus\_download\aes_key.txt      # 默认就扫 E:\tools\vindictus 的 exe 和 pak

key 不是明文躺在 exe 里的：Nexon 用 8 条 mov dword [..], imm32 在运行时把 32 字节拼起来，所以 UnrealKey 之类找连续 32 字节的工具会空手而回。 脚本先扫一遍连续窗口，再收集 .text 里成串的立即数（imm64×4 / imm32×8 / imm8×32）和成对的 xmm 常量，按顺序拼成候选， 拿 Vindictus-Windows.pak 加密索引的前 16 字节做 AES-256-ECB 试解密，解出挂载点 ../../../ 即命中（本机 80 秒）。 命中后写成一行 0x…。之后所有脚本按 VINDICTUS_AES_KEY 环境变量 → -AesKeyFile（默认就是上面这个路径）的顺序取 key， 再经临时文件以 -aes=@file 交给 UE Viewer，命令行里不出现。

key 只放本地文件或环境变量。仓库、CHANGELOG、本页面、聊天记录里都不要出现——和 FF7 Remake 的 key 同一条规矩。

第一步 · 看清单（list_models.py）

python .\list_models.py                          # 36 个模型：id / kind / body / 部件数 / umodel 已导 / blend 已建
python .\list_models.py --kind outfit --json
python .\list_models.py --resolve PCF_003 --json  # 一个模型的包路径、PSK 状态
python .\list_models.py --raw --path-filter /Character/AI/   # 容器里的原始路径

直接解密并解析 Paks\*.utoc 的 IoStore 目录索引（16,703 条路径），不开 UE Viewer。索引只有路径没有类型，所以「部件」= Model\ 下名为 SK_* 且不是 _Skeleton / _Physics / _PhysicsAsset 的资源，再按游戏的拼装方式分组：

kind目录组成
playerCharacter\Player\<Name>\Fiona（女，PCF 骨架）、Lethita（男，PCM 骨架）：Face\Model\SK_<Name>_Face01 + _Hair01 + Armor\Model\SK_<Name>_*_master
outfitCharacter\Outfit\PC{F,M}_Outfit\<Id>\Model\服装部件（Upper/Lower 或 Onepiece + Hand/Foot/Head）+ 对应主角的脸和头发；Player\Outfit\Shiningwill\Mesh 下的旧版整套记作 Shiningwill_legacy（3ds Max Biped 骨架 Bip001_*，脸骨架里还留着这套骨、只是转了 90°，脚本会把它转正再配脸/发）
baseBaseBody_PCM 四件 / Fiona Model\Mesh\SM_pc_fiona_basebody（名字带 SM_ 其实是 SkeletalMesh；旁边的 SK_female_base 是 Skeleton）基础身体 + 脸/发（Fiona 的是白 T 恤 + 短裤的旧版素体）
monster / npcCharacter\AI\<Race>\<Type>\<Variant>\Model\、Character\Npc\**目录下全部 SK（武器标为 weapon，--include-weapons 才并入）

女性角色只有 Fiona 一个（NPC 的 Female_adult 只有骨架）；女装 15 套 = 默认装 + Shiningwill_legacy + 13 套 PCF_*（其中 002/003/005/006/007 是连衣裙）。

第二步 · 一个模型一条命令（export_model.ps1）

.\export_model.ps1 -List                  # = list_models.py
.\export_model.ps1 Fiona                  # 主角默认装
.\export_model.ps1 PCF_003                # 一套服装 + Fiona 脸/发
.\export_model.ps1 PCF_067 -Force         # 重导 + 重建
.\export_model.ps1 Gnoll_type3_Tribe_Boss_01 -NoPreview

三步：list_models.py --resolve 解析包路径（UE Viewer 接受 VindictusRoot/Character/.../SK_xxx 这种 Content 相对路径，避开容器里 178 个重名 stem）； 对缺失的包逐个 umodel_materials_ue5.exe -game=ue5.3 -path=<Paks> -aes=@tmp -export -png -out=<导出根>\umodel_exports <包>， 得到 PSK/PSKX + PNG + .mat/.props.txt（材质实例的贴图、向量、标量参数）；然后写 blend\<id>\spec.json， 无头跑 build_blend.py，解析 VINDICTUS_REPORT= 打印骨骼数、各部件顶点、材质/贴图数、重定位、告警。

build_blend.py 做的事：① UE Viewer 给每个网格导的是它自己的骨架子集（Fiona 脸 658 根、发 274、上身 531、脚 30……），取最多的一副为底按名字补缺、 所有网格重绑到同一副（Fiona 1415 根）；② 部件绑在另一版骨架上的（8 套服装的 Head 脊柱链差 6.9 cm）先把自己的骨架摆到底骨架的 rest 姿势再烘焙， 只有一根 root 的部件（Lethita 头发）挂到 head 骨；③ 材质从 .mat + .props.txt 重建——服装 D/N/ORM|ARM、皮肤 D×Tint、 头发 ODI.R 透明 + FR.B 驱动 Root/Mid/Tip 渐变、眉睫 ODI.R、眼球程序化虹膜（色板采样 → 线性 × IrisBrightness、纤维、limbus、瞳孔）； ④ 贴图拷到 textures\、相对路径保存，渲 preview.png / preview_face.png（相机按脚骨方向判断朝向）。

第三步 · 批量

# 1) 先顺序把包都导出来（UE Viewer 并发会互相覆盖共享贴图，这一步不能并行）
python .\list_models.py --kind outfit --json | ConvertFrom-Json | Where-Object body -eq PCF | ForEach-Object { .\export_model.ps1 $_.id -NoBlend }
# 2) 再分几路并行跑 Blender（PSK 都在了，脚本会跳过 UE Viewer）
foreach ($id in 'PCF_001','PCF_002','PCF_003') { .\export_model.ps1 $id }

每套 Blender 约 2–3 分钟；15 套女装三路并行十几分钟。

产物目录（默认 D:\vindictus_exports）

容易踩的坑

  • Head 部件不都是头盔：项链/颈圈（001、007、009）、耳机（002、004）、帽子（003、012）、发带（006）、发冠（005）、自带发型（001_Temp、008、010 打包了 Fiona 的头发）、全盔（067）。 只有 Head 里带头发材质或 list_models.py 的 HEAD_REPLACES_HAIR（067）标了的才隐藏默认头发；头发仍在文件里（<id>_Hair），要显示就取消隐藏。按几何（贴头皮比例、盖脸比例）分不开耳机和发型，别再试。
  • 部件绑在另一版骨架上：002/003/004/006/007/009/010/012 的 Hand/Head/Upper/Lower 到 head、脚趾差 6.9–13 cm；不重定位帽子会飘在头顶上方。脚本自动烘焙，报告里 reposed_parts 列出。
  • 旧版 Biped 骨架朝向不同：Shiningwill_legacy 和 Fiona 素体绑的 Root → Bip001_* 骨架合并进脸骨架后是第二棵根子树，朝向和 UE 骨架差 90°（面朝 +X），会侧着身、脸朝前。脚本把这棵子树连同绑在上面的网格转正、按 Bip001_Head→head 平移对齐，报告里 aligned_hierarchies；旧装自带的旧发型盖到新脸的眼睛上，所以隐藏旧发型、保留默认头发；素体自带的旧头（Bip001_Head/Neck 权重）整个切掉。
  • 材质参数名要整词匹配："rma" 是 Normal Map 的子串，曾把法线贴图当 ORM 接进去（B 通道≈1 → 金属度 1），没有 ARM 参数的服装全成了金属（PCF_012 的「银裙」、素体的古铜皮肤）。
  • UE Viewer 不能并行：不同模型共用 Fiona 脸/发/眼睛贴图，同时写会互相覆盖。先 -NoBlend 顺序导完再并行 Blender。
  • virtual texture 导不出：静态物件贴图全是；角色里 T_pc_fiona_basebody_01_D（M_female_skin_body_01，PCF_001_Temp 用）也是——这类皮肤材质用纯肤色代替，报告里会列「未解析」。
  • BC6H 贴图写成 .hdr：PCF_012 的 _B 基色是 .hdr，脚本已按 .hdr 索引；别按 png 去找。
  • PCF_001_Temp 是 WIP 服装：裤子的彩虹格/棋盘是资源自带的占位贴图，不是导出坏了。
  • 眼睛：T_Iris_A_M 的 B 是径向渐变、G 是纤维、alpha 是瞳孔，不是遮罩；从色板贴图采到的颜色是 sRGB 值，喂给节点前要转线性——否则虹膜是一团白雾。
  • UE Viewer 报 Oodle 解压错误：多半是下载的包坏了，核对 md5。
  • morph target 导不出（脸包里的 MetaHuman DNAAsset 也不导），面部没有形态键；Nanite 只有基础几何。

重新生成本页
