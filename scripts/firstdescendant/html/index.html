附录 · 手工导出教程

脚本都在 scripts\firstdescendant\，产物默认落在 D:\tfd_exports（-ExportRoot）。 这套和别的游戏最大的不同：贴图全是 UE5 虚拟贴图（Virtual Texture），UE Viewer 一张都导不出来（日志里写 it's a virtual texture，Exported 0/0），必须换 CUE4Parse；而 CUE4Parse 解本作任何属性都要一份 .usmap（包是 unversioned properties），这份映射表在 Nexus 上已被下架，只能从论坛翻。顺序固定： 装游戏 → 算 AES key → list_models.py 看清单 → export_model.ps1 <模型> 出带贴图的 .blend → 重生成本页。 以下命令都在 〈仓库〉\scripts\firstdescendant 里跑，每开一个新窗口先 cd 进去。

前提 · 工具与默认路径

第零步 · 算 AES key（find_aes_key.py，只做一次）

python .\find_aes_key.py --out D:\tfd_exports\_keys\aes_key.txt

和 Vindictus 同一个 Nexon 套路：key 不是明文躺在 exe 里，而是运行时用 8 条 mov dword [..], imm32 拼出来的， 找连续 32 字节的工具会空手而回。脚本扫 M1-Win64-Shipping.exe 的 .text，把成串的立即数按顺序拼成候选， 拿 M1-Windows.pak 加密索引的前 16 字节做 AES-256-ECB 试解，解出挂载点即命中（本机 60 秒，命中点在文件偏移 0x458850B）。 之后所有脚本按 TFD_AES_KEY 环境变量 → -AesKeyFile 取 key。

key 只放本地文件或环境变量。仓库、CHANGELOG、本页面、聊天记录里都不要出现。 （cue4parse.exe 没有 key 文件参数，key 会出现在它的命令行上，本机使用可接受。）

第一步 · 看清单（list_models.py）

python .\list_models.py                        # 2067 个模型：id / kind / char / 部件 / 已导 / blend

直接解密 Paks\*.utoc 的 IoStore 目录索引取全部路径，不开任何外部工具。索引只有路径没有类型，所以「网格」靠目录 + 命名判： 在 /Skel/ 或 /MESH/ 下、不在 /Material/ /Texture/ /Textuer/ /Anim/ /BP/ 里、不以 BP_ ABP_ CIN_ 开头、 不以 _AnimBP _AimOffset _Skeleton _Physics _MI 等结尾。

kind容器里的位置组成
descendant（33）PC/MESH/PRESET/<名字>/PC_<编号>_<A|U>0101 21 个角色 + 12 个 Ultimate（A 标准 / U Ultimate）。默认装就是这一整块合并网格（身体+头+头发+脸，带面部 morph），导出最干净。

第二步 · 一个模型一条命令（export_model.ps1）

.\export_model.ps1 Viessa                 # 后裔默认装
.\export_model.ps1 Bunny_CMN_001          # 一套皮肤（Body + Head 配件 + Face）

四步，全自动：

  1. list_models.py --resolve 解析出这个模型要哪几个包；
  2. CUE4Parse 逐包导 ActorX pskx：-g GAME_TheFirstDescendant -m <usmap> --mesh-format ActorX --export-materials。 出来的 pskx 带真实材质槽名（PC_003_A0101_PartA_MI 这种）、morph target、顶点色；
  3. resolve_textures.py：槽名 → 材质实例包 → 用 iostore.py 读它的 zen 名字表拿到引用的贴图名 → CUE4Parse 一次把这些虚拟贴图解码成 PNG → UE Viewer 读材质参数，汇总成 materials.json；
  4. Blender 无头跑 build_blend.py：合成一副骨架、按槽建材质、渲两张预览、存 .blend（贴图拷进 textures\ 用相对路径）。

末尾解析 TFD_REPORT= 打印骨骼数、每个部件的顶点 / 槽 / morph 数、材质与贴图张数、未解析贴图、告警。 整个 blend\<id>\ 目录可以直接拷给别人。

usmap 从哪来（最麻烦的一步）

本作的包是 unversioned properties（我直接读包头标志确认的），没有 .usmap 时 CUE4Parse 只会报 Could not load standard asset, check game version, mappings or keys。Nexus 上原来的两个映射 mod （thefirstdescendant/mods/1 和 mods/5）已被下架——用公开 GraphQL 接口查过，整个板块只剩 1 个壁纸 mod。 现在用的是 Gildor 论坛 TFD 帖（topic 9006）第 7 页网友发的 MediaFire 文件 Mappings.usmap（2024-07-16）。 它是发售版的映射，两年后已部分过期：

  • 能解：Texture2D / 虚拟贴图、SkeletalMesh（含材质槽名、morph、顶点色）→ 网格和贴图全靠它；
  • 不能解：MaterialInstanceConstant（报 Invalid bool value），所以「这个材质引用了哪些贴图」读不出来。 这块由 iostore.py 补：自己解容器（AES-ECB 分块 + Oodle）、自己读 zen 包头的名字表（UE 5.2 的 44 字节 summary）， 完全不需要 usmap——一个材质实例的名字表里就明晃晃列着它引用的全部贴图名。

自己生成新 usmap 要往带 EAC + Nexon 反作弊的游戏进程里注入 Dumper-7 / UE4SS，有封号风险，没做。 另一个坑：拿通用的 -g GAME_UE5_2 代替 TFD 专用枚举，网格能出但贴图会解坏 （Failed to parse pixel format: PF_DXT5_0、Serialized FString is not null terminated）。

贴图约定（build_blend.py 按这个建材质）

后缀内容用法
_C颜色Base Color（sRGB）
_N法线，DirectX 约定翻绿通道再进 Normal Map
_P打包图 R=AO，G=粗糙度，B=金属度（alpha≈0） 必须按 Channel Packed 读，否则 alpha 预乘会把 RGB 抹黑；皮肤的 _P 是另一个母材质（B 恒 255），金属度强制 0
_ID六色硬边区域遮罩（红/绿/蓝/品红/黄/青 = 染色区 A–F）玩家染色系统用；默认外观直接用 _C，没接
_FX自发光遮罩（R）× 材质参数 Emissive_col
Female/Male_HairTex_NNN_P共享发丝图：A=透明度，G=发根→发梢，R/B=深度/AO 颜色 = Hair_RootColor → Hair_TipColor 按 G 混合
眼睛T_Sclera_D + T_Veins_D + T_Eye_N；虹膜是 MetaHuman 式程序化（IrisColor1U/V 去 iris_color_picker 取色） 巩膜贴图 + 程序化虹膜圆盘（颜色目前是近似棕色，取色还没接）
眉 / 睫父材质的 T_eyebrow_d / T_eyelash2_D深色 + alpha
*Glass_MI面罩参数 Color/Opacity/Roughness → 半透明
EyeOCC / TearLine眼部遮挡壳 / 泪线全透明

材质实例名就是 pskx 的槽名，classify() 按名字和贴图判类型。游戏方的拼写要注意：Eyeblow（= 眉毛）、 Textuer、_Ml；Head_999_MI 这种不带 hair 字样的按有没有 HairTex 贴图识别； Face_Dyed_Mask 是参数名不是贴图，别去找。

多部件怎么合

  • 同骨架部件（皮肤的 Body / Face）：按骨名并入底模骨架，缺的骨按父子关系补进去。 Blender 坑：跨 mode_set 切换后不能再读旧的骨引用（会 UnicodeDecodeError），合骨前先把骨名 / 坐标拉成普通值。
  • socket 配件（皮肤 HEAD 里的头盔：自带 Head_Root → Pt_Head → Bn_Socket_* 三根骨、和角色骨架无一根同名、网格画在原点）： 不能蒙皮，整体骨父级到底模的 Bn_Socket_Head（退而求其次 Bip001-Head），用该骨的完整矩阵。不这么做它会掉在脚边。
  • 部件自己的骨和底模同名骨位置不一致时，用最靠根的共享骨算刚体差把部件挪过去（同骨架时为恒等）。
  • 骨架是 3ds Max Biped：Bip001-Head、Bn_*、Pt_*、Dm_*。

容易踩的坑

  • PowerShell 5.1 + 原生程序的 stderr：cue4parse 把日志写 stderr，在 $ErrorActionPreference='Stop' 下配 2>&1， 第一行日志就会变成终止性的 NativeCommandError。调用处临时切 Continue，finally 里切回来。
  • .ps1 里的字符串必须全 ASCII：PowerShell 5.1 按 OEM 代码页读无 BOM 的 .ps1，引号里的多字节中文会把解析搞坏。中文放 Python / Markdown 里。
  • 打包图别用默认色彩空间：_P 的 alpha≈0，Blender 里不勾 Channel Packed 就会预乘成黑的，模型全成了 AO 全黑。
  • 怪物清单会混进蓝图：BP_ / ABP_ / _AnimBP 也在 MESH/ 下，不过滤会把 201 只怪虚报成几百。
  • 一个目录里有多个变体：MOB_CMN_1001 下同时有 A001 和 B001，按主网格分组（id = 网格名）才不会被合成一个。
  • 预览图取脸的位置按 Bip001-Head 找；相机 sensor_fit = VERTICAL，否则竖构图会把人裁掉。

已知局限

  • 虹膜颜色是近似值：游戏用 IrisColor1U/V 去 iris_color_picker 取色，图已经解出来在 cue4_exports\M1\Content\BaseMaterials\Character\Material\Eyes\Texture\，采样还没接。

  • 本页所有路径都是本机 file://，换机器要重新导出 + 重新生成。
